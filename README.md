# Optical Data Communication System

光学的な視覚通信を用いて、QRコードまたはAprilTagを介してテキストやファイルを送受信する実験プロジェクトです。

このリポジトリは、ブラウザ上で送信側を動かし、Webカメラで受信側を読み取るデモを実現します。通信の途中でデータを分割し、再構成する仕組みを使って、画面上のマーカー群から文字列を復元します。

## 概要

- 送信方式
  - QRコード
  - AprilTag
- 対応モード
  - 送信 (Sender)
  - 受信 (Receiver)
- 送信データ
  - テキスト
  - ファイル
- 特徴
  - ブラウザのみで動作する送信画面
  - Webカメラを使った受信と再構成
  - チャンク分割による大きなデータの送信
  - ROI（解析領域）固定による受信安定化

## ディレクトリ構成

- `index.html` : Web UIと送受信ロジック
- `Calculation.js` : データ分割・ヘッダー生成・再構成ロジック
- `Sender_QRCode.py` : Python版のQR送信デモ
- `Receiver_QRCode.py` : Python版のQR受信デモ
- `Sender_Apriltag.py` : Python版のAprilTag送信デモ
- `Receiver_Apriltag.py` : Python版のAprilTag受信デモ

## 使い方

### 1. ブラウザ版を起動する

ローカルサーバーで開くのが安定します。

```bash
python -m http.server 8000
```

その後、ブラウザで以下を開きます。

```text
http://localhost:8000/
```

### 2. 送信側を設定する

- 通信モードを `送信` に切り替える
- テキストまたはファイルを選ぶ
- 方式を `QRコード` または `AprilTag` に選ぶ
- `FPS` と `N×N` を設定する
- `通信実行` を押す

### 3. 受信側を設定する

- 通信モードを `受信` に切り替える
- 使用するカメラを選ぶ
- 解析枠の固定が必要なら `解析枠を固定する` を有効化
- `通信実行` を押す
- 画面に表示されたマーカーをカメラで読み取る

## 実装上の注意点

このプロジェクトは「実験的な視覚通信デモ」であり、現実の高信頼通信システムではありません。

- 画像の明るさやカメラ性能に大きく依存します
- QRの認識率は環境によって変動します
- AprilTagは実装状態と再現性に差が出やすいです
- 本番用途ではエラー訂正や再送制御が必要です

## 最新アップデート（機能追加報告）

2026/09/30 時点で、基礎的な視覚通信デモに加えて、実運用に近いトランスポート層を導入しました。

### 追加した機能

- セッション ID 管理
  - `HELLO` を使って送受信の session を確立
- ACK 応答
  - 受信した chunk ごとに `ACK|session|chunk|ok` を発行
- 欠損 chunk 検知
  - 受信済み chunk と総 chunk 数から不足分を自動計算
- 再送キュー
  - `missing` ACK を受けて送信側が再送対象を積み上げ
- 同時通信デモ UI
  - Sender / Receiver の状態を同時に可視化するデモパネルを追加
- 実行中状態の可視化
  - 進捗、再送対象、最後の ACK を UI 上で確認可能

### これでできるようになったこと

- 受信側が「何が欠けているか」を把握できる
- 送信側が「どこを再送すべきか」を把握できる
- Web UI 上で session と transport 状態が追跡できる
- そのままデモ発表用の説明資料として使える状態になっている

### 使い方

- 通常の送信/受信モード
  - そのままブラウザで送信と受信を実行可能
- 同時通信デモ UI
  - フォーム上部の `🎭 同時通信デモUI` を押すと、Sender / Receiver の状態が並列表示される
